# Claude Code finance skills

These repository skills provide procedures and generic SAP reference material. They do not contain company schemas or financial data, and do not establish that a query has run. The live Databricks contract remains in `databricks-agent-toolkit/AGENTS.md`.

## Use in Claude Code

Open this repository as the Claude Code workspace, then check `/skills`. The skills can load when a request matches their descriptions; invoke one explicitly when you want to ensure it is used.

| Command | Purpose |
| --- | --- |
| `/databricks-query` | Verify the live schema, formulate bounded SQL, and validate execution and totals. |
| `/sap-materials` | Material master, plant, storage, valuation, units, and descriptions. |
| `/sap-fi-open-items` | Accounting documents, AR/AP/GL open and cleared items, key dates, currencies, and signs. |
| `/sap-profit-center` | Classic ECC profit-center line items versus totals, GLPCA/GLPCT, periods and record types. |
| `/sap-sd-mm` | Sales, delivery, billing, purchasing, and goods-movement document relationships. |
| `/finance-handoff` | Write a concise investigation checkpoint with evidence paths, unresolved questions, and next steps. |

Example prompts:

```text
/databricks-query Find the actual landed BSEG table in the approved schema,
verify its columns and grain, then draft a bounded read-only query.

/sap-profit-center Explain whether GLPCT or GLPCA fits a monthly PCA
reconciliation. Keep unknown company configuration explicit.

/finance-handoff Save where we are before I clear this session.
```

Typing a command into a chat that is not Claude Code does not install these skills. A GitHub URL alone does not register them. To use them in another approved local project, copy the required skill directories into that project's `.claude/skills/`, and adapt its `CLAUDE.md` routing. Keep the Databricks execution contract available with the skill. Merge any hook settings with that project's existing settings; never overwrite managed company settings.

## Reduce context while retaining interactive problem solving

Keep the conversation interactive. The durable record should capture what was learned, rather than every turn that led there.

1. Use a small `CLAUDE.md` as a router. Load the relevant SAP family only when needed. Do not attach a complete table dictionary or all historical chat exports to each request.
2. Save working SQL and code to files. Ask Claude to change a specific part and show the result or diff. Persist verified schema/grain notes beside the project, with workspace/catalog identity, verification time, and evidence paths; recheck them when the target or schema changes.
3. Aggregate in Databricks and keep tool output narrow: required columns, a bounded period, small samples, concise error text. A SQL `LIMIT` controls returned rows, not scan cost. Never treat a sample or truncated result as the full population.
4. At a milestone, invoke `/finance-handoff`. Aim for about 300–600 words or less: objective, verified facts, failed approaches, artifacts, blocker, next action. Store detailed results separately. This is a working target, not a guaranteed token count.
5. Use `/compact` with a focus instruction while continuing the same investigation. For a different task, checkpoint, clear, and load only the handoff you intend to resume. Use `/context` to inspect what is filling the window.
6. Select the least expensive company-approved model that solves the current step. Straightforward schema inspection and SQL edits often need less reasoning than an unresolved financial reconciliation. Avoid launching agents that all reread the same large context; give independent investigations narrow scopes and brief return summaries.

## Automatic Markdown after compaction

The optional project hook saves Claude Code's built-in compaction summary locally when `PostCompact` fires. It makes no additional model or network call. Compaction itself still consumes model tokens, and saving Markdown alone does not shrink a conversation; `/compact`, automatic compaction, or a fresh session changes the active context.

`COMPACTION.md` is a continuity snapshot generated by Claude Code. `/finance-handoff` is the deliberate checkpoint you can review before a reset. Neither is proof that an inferred mapping or query is correct.

Use the existing approved Python 3.8+ interpreter for the hook. The supplied configuration requires Claude Code 2.1.139+ for hook argument arrays; `PostCompact` was added in 2.1.76. Check `claude --version` and the [hook notes](../.claude/skills/finance-handoff/references/hook-notes.md) before enabling it. If Python is invoked by a different command at your company, adjust only the interpreter in the project hook configuration. Managed policy may prevent project hooks from running; in that case the handoff skill and normal `/compact` still work. Do not bypass policy or install a second client to avoid it.

Generated state is ignored by Git. It can still contain company information and must stay on approved storage. Git ignore rules do not replace company data policy. No transcript export or automatic publication of handoffs is enabled.

## Company gateway and measured savings

Keep the company LiteLLM endpoint, credentials, allowed models, and retention rules as configured by IT. Prompt-cache behavior and pricing depend on the gateway and upstream provider. `/cost` may be useful as a client estimate, but use the company's gateway usage records for charged spend, including cached input, output, compaction, retries, and agent calls. Do not assume every context token is billed at the uncached rate or that every call is cached.

Ask the platform owner to verify that the Claude route preserves `cache_control` markers and block-form system/message content, and that repeated eligible turns report `cache_read_input_tokens` above zero. If all eligible turns show zero, investigate routing, provider support, or per-request rewrites of the prompt/tool list. This is a diagnostic for the existing approved route, not a reason to change credentials or bypass a guardrail. Avoid switching models repeatedly during one investigation: their caches are separate.

Compare similar completed tasks before and after this workflow: actual spend, total tokens, number of schema rediscoveries, failed query attempts, and whether the financial result reconciled. There is no justified percentage savings claim until those measurements exist.
